## Answers to 14 Audit Questions

### Q1 — Amazon Tag Canonical

**Finding: Tag conflict — different fallbacks in two configs.**

| Location | Tag |
|----------|-----|
| `src/lib/amazon/amazonConfig.ts` line 2 | `import.meta.env.PUBLIC_AMAZON_TAG \|\| 'pupwiki-20'` |
| `src/lib/site-config.ts` line (AFFILIATE_TAG) | `import.meta.env.PUBLIC_AMAZON_TAG \|\| 'aiexpertscorn-20'` |

Both read from the same `PUBLIC_AMAZON_TAG` env var. If the env var is set in production (Cloudflare Pages), the correct tag is used. If it is missing or unset, `amazonConfig.ts` falls back to `'pupwiki-20'` while `site-config.ts` falls back to `'aiexpertscorn-20'`.

**Where each tag source is used:**

- `site-config.ts / AFFILIATE_TAG`: Used in `src/data/affiliate-links.ts` (Amazon search URLs), `src/pages/dog-names/[breed].astro` (hardcoded `'aiexpertscorn-20'`), `src/pages/brands/brand-page.astro` (hardcoded `'aiexpertscorn-20'`), component defaults in `SidebarWidget`, `ComparisonTable`, `PriceComparisonWidget`, `VerdictBox`, `InlineCTA`, `ProductReviewCard`, `ProductCard`, `ProductGrid` — all hardcode `'aiexpertscorn-20'` directly.

- `amazonConfig.ts / AMAZON_ASSOCIATE_TAG`: Used in `src/lib/amazon/amazonDeeplink.ts` → `buildAmazonSearchUrl()`. This function generates Amazon keyword search fallback URLs (e.g. `https://www.amazon.com/s?k=dog+food&tag=pupwiki-20`). These fallback search links are served when no exact ASIN product matches a page context — every `AmazonProductSlot` that finds no direct product match will emit links with the wrong tag unless `PUBLIC_AMAZON_TAG` is set.

- Pre-built ASIN product links in `amazon-products.json` use `amzn.to` shortlinks generated by Amazon SiteStripe. The tag is embedded in the redirect; runtime code cannot verify or override it.

**Verdict:** If `PUBLIC_AMAZON_TAG=aiexpertscorn-20` is set as a Cloudflare Pages environment variable, no live commission is lost. Verify this is set. Regardless, the fallback should be fixed to `'aiexpertscorn-20'` in `amazonConfig.ts` to be safe.

### Q2 — Duplicate AmazonProductSlot

Two files exist:

| File | Imports | Props | Used by |
|------|---------|-------|---------|
| `src/components/amazon/AmazonProductSlot.astro` | `AmazonBadge`, `matchAmazonProducts` | `headline`, `eyebrow`, `note`, `variant` (`rail`\|`compact`) + full `AmazonPlacementContext` | `BreedCommerceSuite`, `ArticleCommerceSuite`, `ContentClusterHub` |
| `src/components/affiliate/AmazonProductSlot.astro` | `AmazonProductCard`, `AmazonDisclosure`, `AmazonClickTracker` + CSS import | Adds `description`, `placement`, `columns`, `showDisclosure` on top of context props. Variant: `card`\|`compact` | `CategoryAmazonBlock` (category pages only) |

**Neither is fully orphaned.** The `src/components/amazon/` version handles the majority of traffic (breed pages and blog articles). The `src/components/affiliate/` version handles category pages.

**Key feature gap:** The `amazon/` version (serving breed + blog) renders product cards via `AmazonBadge` without `AmazonDisclosure` or `AmazonClickTracker`. The `affiliate/` version (serving only category pages) has both. This means:
- Breed pages and blog articles have no Amazon click tracking.
- Breed pages and blog articles have no inline Amazon disclosure text.
- The GTM Amazon click event (`AmazonClickTracker`) fires only on category pages.

**Recommendation for Phase 2:** Consolidate to one component. Add `AmazonDisclosure` and `AmazonClickTracker` to the `amazon/` version (which has more coverage), or route all usage to the `affiliate/` version. Delete the other.

### Q3 — AWIN Matching Logic

**File:** `src/lib/awin/matchProducts.ts`

`matchProducts(products, context)` flow:
1. No `enabled` filter — all products in the loaded array are scored.
2. Excludes product IDs listed in `context.excludeProductIds`.
3. Scores each product via `scoreProduct()`:
   - Page type match against `program.pageTypes`: **+2**
   - Topic tag overlap (context vs. program tags): **+3 per match**
   - Category match against program tags: **+2**
   - Product-level topic tag overlap with context tags: **+2 per match**
   - Program priority base: **+(priority ?? 50) / 40** (e.g. ChefPaw priority=85 → +2.125)
   - High intent + buyer-signal product name: **+1.5**
   - Image present: **+1**
   - Non-tidd.ly deep link: **+1**
   - Breed size name match: **+1**
4. Sorts by score descending.
5. **Deduplicates to one product per merchant** (line 111 — `findIndex` keeps first occurrence per merchant after sort).
6. Returns top N.

**When no match:** Returns empty array. `AwinProductSlot` renders nothing (no fallback to Amazon or any other network). There is no graceful degradation text.

**Data fallback:** `AwinProductSlot.astro` tries `awin-products.json` first; if empty, tries `affiliate-products.json`. `affiliate-products.json` is manually maintained as a static fallback list.

### Q4 — AWIN-First Policy Compliance

**The AWIN-first policy is documented but not enforced in code.**

| Page type | AWIN present | Amazon present | Enforcement |
|-----------|-------------|----------------|-------------|
| Breed pages (`BreedCommerceSuite`) | ✅ 2 slots | ✅ 1 slot (parallel) | None — both render independently |
| Blog articles (`ArticleCommerceSuite`) | ✅ 1 slot | ✅ 1 slot (parallel) | None — both render independently |
| Category pages (`CategoryAmazonBlock`) | ❌ | ✅ | No AWIN check at all |
| Cost calculator (`[breed].astro`) | ✅ | ❌ (removed) | N/A |
| Dog names (`[breed].astro`) | ✅ | ❌ (removed) | N/A |

On category pages, `CategoryAmazonBlock` renders Amazon products without first checking whether an AWIN product exists for the context. This does not technically violate a "no Amazon without AWIN" rule (no such code constraint exists), but it means category pages are Amazon-only for commerce.

**Recommendation:** If AWIN-first is a revenue priority, add `AwinProductSlot` to category pages and gate `CategoryAmazonBlock` on `showAmazonIfNoAwin` logic. For Phase 2, the Amazon link engine could infer whether to show an Amazon CTA based on whether AWIN already covers the slot.

### Q5 — Amazon Product Data Freshness

**Display-only fields (safe to go stale):**
`name`, `brand`, `categoryGroup`, `categoryLabel`, `recommendedPlacement`, `amazonSearchQuery`, `topicTags`, `complianceRisk`, `salesIntent`, `targetPageSlugs`, `liveSearchNote`, `priorityScore`

**Functional fields (must remain accurate):**
`enabled`, `asin`, `amazonAffiliateUrl` (the amzn.to shortlink), `isLiveEligible`, `liveSearchStatus`

**Data storage:** `amazon-products.json` does NOT store prices, ratings, or product images. The `sync-amazon-products.mjs` script reads from the SiteStripe CSV and only persists the functional and editorial fields. Prices and ratings are not exposed in any component output.

**Staleness risk:** Pre-built `amzn.to` shortlinks are created by Amazon SiteStripe at a point in time. If an ASIN is delisted or the product page changes significantly:
- The `amzn.to` redirect may still work (Amazon keeps shortlinks alive) but land on a different page.
- The `liveSearchStatus` field (`'validated'`, `'generated-search-template'`) is not auto-refreshed between CSV exports.
- There is no scheduled job to re-validate shortlinks.

**Recommended policy:** Treat `amazonAffiliateUrl` as needing re-export from SiteStripe every 60–90 days. Add a `lastVerifiedAt` timestamp to the product schema in a future sync run.

### Q8 — Partner Posts Audit

**CRITICAL FINDING: Partner posts 404 in production but are listed in the sitemap and linked from the partners directory.**

Posts with `indexInBlog: false`:
- `dog-beds-comfort-home-partners.md`
- `dog-food-nutrition-partners.md`
- `dog-health-wellness-adjacent-partners.md`
- `dog-training-gear-safety-partners.md`
- `partner-brutus-broth.md`
- `partner-chefpaw.md`
- `partner-crownandpaw.md`
- `partner-jugbow.md`
- `partner-mypetdmv-the-original-pet-drivers-license.md`
- `partner-radiofence-com.md`
- `partner-raw-wild-llc.md`
- `personalized-dog-gifts-lifestyle-partners.md`

**Why they 404:**
`src/pages/blog/[slug].astro` → `getStaticPaths()` → `.filter(isPublicBlogEntry)` → `isPublicBlogEntry` returns `false` when `post.data.indexInBlog === false`. No static file is generated. Any request to `/blog/partner-jugbow` returns 404 in production.

**Why they appear in the sitemap:**
`generate-sitemap.mjs` line 107-117 scans the `src/content/blog/` directory directly (filesystem walk) and adds every `.md` file to the sitemap without checking `indexInBlog`. The comment at line 107 explicitly notes "including generated partner profiles."

**Why they're linked:**
`pupwiki-partners.astro` → `profileHref()` → falls back to `/blog/partner-${program.key}`. The "Read guide" button on each brand card links to these non-existent routes.

**Root cause:** `indexInBlog: false` was designed to exclude posts from the blog feed/index. `isPublicBlogEntry` uses this same flag to gate static path generation — conflating "hide from feed" with "don't generate page." These are different concerns.

**Fix options (for Phase 2):**
1. Add a separate `noRoute: true` flag for truly private posts; let `indexInBlog: false` only affect the blog feed.
2. Remove partner posts from the sitemap generator, remove links from the partners directory, and accept that these pages don't exist.
3. Make partner posts fully routable (`indexInBlog: false` only removes from feed) and gate the AWIN/commission body content behind a build-time strip.

### Q12 — Script Health

**`scripts/sync-amazon-products.mjs`**
- Reads from SiteStripe CSV (`amazon-products-live-checked.csv`).
- If CSV is missing but `amazon-products.json` already exists: exits 0 (safe build behavior).
- `--strict` flag: fails if CSV is missing (for enforced refresh).
- Writes to `src/data/amazon-products.json` and `amazon-products-summary.json`.
- CI-safe: the `:ci` variant (`amazon:sync` in `prebuild`) exits 0 gracefully on missing input.
- No network calls — operates on local CSV only.

**`scripts/sync-awin.mjs`**
- Requires `AWIN_OAUTH2_TOKEN` env var for live programme sync.
- Has `AWIN_SYNC_DISABLED=false` env override to skip entirely.
- Has `AWIN_ALLOW_FALLBACK_WRITE=false` env to prevent overwriting existing files on failure.
- Writes to `src/data/awin-programs.json`, `awin-products.json`, `affiliate-banners.json`.
- CI-safe: if token is missing, falls back gracefully without overwriting existing data files.
- Network-dependent — AWIN API failure could silently leave stale data in place.

**Both scripts are CI-safe and write to `src/data/` directly.** Committed JSON files serve as stable fallbacks when scripts fail or are skipped.

### Q13 — `getActiveBanners` / `getActiveOffers`

**`getActiveBanners` (`src/lib/affiliate/getActiveBanners.ts`):**

Selection pipeline (all filters must pass):
1. `banner.enabled === true`
2. Date window: `startAt` ≤ now ≤ `endAt` (if fields present)
3. `!context.isMedical` — **if `isMedical=true`, ALL banners are blocked regardless of banner type**
4. `banner.pageTypes` includes current page type (or is empty → match all)
5. `banner.placements` includes current placement (or is empty → match all)
6. NOT in `banner.excludePageTypes`
7. `banner.topicTags` overlaps context tags (or banner has no topic tags → match all)
8. NOT in `banner.excludeTopicTags`

Sorted by priority descending. Returns first match via `getFirstAffiliateBanner()`, or `null`.

**When all banners expire or none are enabled:** Returns `null`. `PageBannerSlot` renders nothing — no fallback content, no empty state placeholder.

**When `isMedical=true`:** All banners blocked at step 3. This applies even to non-medical banners — it is a page-level block, not a banner-level flag.

**`getActiveOffers` (`src/lib/affiliate/getActiveOffers.ts`):**

Filters: `enabled`, `placement`, `pageType`, `claimSensitivityBlock`, tag/intent match. Returns sorted array; caller takes `[0]`.

**All offers in `affiliate-offers.json` are `enabled: false`.** No offers have been activated. `OfferSlot` renders nothing on every page in production.

No date-based expiry logic in `getActiveOffers`.
